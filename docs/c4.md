# C4 resumido

## Contexto

Operador → Console React → API Flask/controlador → processos CDN locais → monitor e plataforma externa simulada.

## Containers

- **Console**: Vite + React + TypeScript + Leaflet; apenas renderiza DTOs da API.
- **Control plane**: Flask/Flask-RESTX, ciclo de vida, roteamento e observabilidade.
- **CDN node**: processo Flask independente por nó; streaming, estado local, health e gossip.
- **Evidence feed**: `LeakService` produz evidência simulada; `MonitorService` lê apenas seu escopo.
- **Repositories**: memória limitada; interfaces de provider deixam persistência futura isolada.
- **Management domain**: motor em memória para saldo, demanda, custos, cenários e seis ações econômicas; consulta telemetria dos nós, mas não a substitui.

## Fluxos

1. **Dados**: cliente → controller → nó saudável; atraso artificial, RTT HTTP e E2E são medidos separadamente.
2. **Controle**: controller → nós com assinatura HMAC de transporte; configura peers/faults/reconcile.
3. **Evidência**: chunk → plataforma simulada → monitor do nó de origem → prova → blacklist → gossip/ACK/retry.

Mensagens potenciais entre coordenadas não são desenhadas como mensagens observadas: a UI usa eventos efetivamente registrados.
